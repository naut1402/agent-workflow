# Project Structure — dev-team-dashboard

A Vue 3 + Vite SPA that **visualizes the runtime state of the dev-agent-teams orchestrator** (a separate Claude Code plugin). The dashboard reads task/pipeline state from a `.dev-team-agent/` workspace folder and is read/write for *configuration* (pipelines, custom agents, templates, knowledge). It never runs the orchestrator itself. UI language is Vietnamese.

## Top-level layout

```
agent-workflow/
├── index.html              # SPA entry; loads /src/main.js
├── vite.config.js          # Vite + Vue plugin + devTeamApi middleware; dev port 5174
├── package.json            # ESM ("type":"module"); pnpm; scripts: dev/build/serve/start/mcp
├── pnpm-workspace.yaml
├── src/                    # Vue 3 frontend (SPA)
├── server/                 # Backend: shared API handler, registry, knowledge drivers
├── mcp/                    # MCP stdio server (project-registry CRUD for Claude Code)
├── tests/                  # unit tests mirroring source (bun test: server/mcp · vitest: src/shared)
├── test-e2e/               # @playwright/test specs + fixtures/.dev-team-agent/
├── dist/                   # Build output (generated by `bun run build`)
└── .claude/
    ├── settings.local.json # enables the dev-team-dashboard MCP server
    └── rules/              # project rules (this file)
```

## The data root (`.dev-team-agent/`) — the central concept

Every backend read/write is scoped to a **`.dev-team-agent/` directory** ("the root"), owned by the orchestrator plugin — not this repo. It contains:

- `.dev-state/<task-id>.json` — per-task live state (current_phase, hitl_pending, review_round, doc_review_round, …)
- `tasks/<task-id>/*.md` — phase artifacts: `investigate.md`, `design.md`, `phpstan.md`, `review.md`, `test-spec.md`, `pr-desc.md`, `qa.md`, plus `*-po.md` doc-review sidecars and machine-only `pipeline-export.json`
- `pipeline.yaml` (global) and `tasks/<id>/pipeline.yaml` (per-task) — pipeline overrides
- `pipeline-profiles/`, `custom-agents/`, `agent-templates/`, `workflow-step-templates/`, `flow-profiles/` — dashboard-managed config
- `knowledge/` + `knowledge.config.yaml` — file-driver knowledge store

**Root resolution (two run modes):**
- **Dev mode** (`vite.config.js` → `devTeamApi` plugin): root = `cwd/..` (dashboard is meant to be scaffolded into `.dev-team-agent/viewer/`), overridable via `DEV_TEAM_ROOT`. Legacy single-project.
- **Standalone / multi-project** (`server/standalone.js`): roots come from the **ProjectRegistry** at `~/.dev-team-dashboard/projects.json` (dir override: `DEV_TEAM_DASHBOARD_HOME`). Requests carry `?project=<id>`; no id → default project (DEV_TEAM_ROOT env > registry default > legacy fallback). See `resolveProjectRoot` in `server/registry.js`.

## Backend (`server/`)

| File | Role |
|------|------|
| `devTeamApi.js` | **Core of the backend.** Exports `createApiHandler(ctx)` → an `(req,res)=>boolean` dispatcher for all `/api/*` routes (returns `false` for non-API paths). Also exports `devTeamApi({root})`, the Vite middleware wrapper. Contains catalog scanning, pipeline-config resolution, artifact listing, profile/agent/template CRUD. |
| `standalone.js` | Neutral Node HTTP server: serves `dist/` (SPA fallback) + mounts `createApiHandler`; binds `127.0.0.1:5174`. Run via `pnpm serve` (needs `dist/`). |
| `registry.js` | **Single source of truth** for the ProjectRegistry (`projects.json`), shared by REST API *and* MCP server. Path validation (`validateProjectPath` via `realpathSync`), atomic saves, `resolveProjectRoot`, `createRegistryContext`. |
| `knowledge/knowledgeApi.js` | REST surface for `/api/knowledge*` (list/read/write/delete/upload/tags). |
| `knowledge/driverRegistry.js` | `getKnowledgeDriver(root)` — pluggable driver lookup from `knowledge.config.yaml` (only `file` exists today). |
| `knowledge/fileDriver.js` | File-backed knowledge store under `<root>/knowledge/`; markdown + YAML frontmatter, slug/tag sanitization, 512KB upload cap. |

**One handler, two transports:** `devTeamApi.js`'s handler is mounted both as Vite middleware (dev) and by `standalone.js` (prod). Edit API behavior once; both modes inherit it.

**Layered pipeline config** (`loadPipelineConfig`): built-in `DEFAULT_PIPELINE` ← global `pipeline.yaml` (full replace) ← per-task `tasks/<id>/pipeline.yaml` (patch by step `id`, or full replace via `steps_replace`/all-new-ids). `DEFAULT_PIPELINE` is a hand-kept JS mirror of the plugin's `pipeline.default.yaml` — keep them structurally in sync.

**Catalog** (`buildCatalog`): aggregates skills+agents from enabled installed plugins, plugin cache, `~/.claude/skills|agents`, `~/.cursor`, repo `marketplace.json`, project `.claude/`, and dashboard `custom-agents/`; deduped by `name` via `sourcePriority`; `BUILTIN_CATALOG` fallback.

## MCP server (`mcp/`)

`server.mjs` — stdio MCP entrypoint (`pnpm mcp`) exposing project-registry CRUD (`list_projects`, `get_project`, `add_project`, `remove_project`) to Claude Code via `server/registry.js`. Does **not** require the HTTP server. Enabled through `.claude/settings.local.json` → `enabledMcpjsonServers`.

## Frontend (`src/`)

- `main.js` — mounts `App.vue`; `style.css` is the global stylesheet.
- `api.js` — thin `fetch` wrappers for every endpoint, the `?project=` query builder (`qs`), and phase-status derivation (`PHASES`, `phasesFromPipeline`, `phaseStatus`). Phase status is **inferred from artifact existence** + live cursor, mirroring the orchestrator's own rule.
- `App.vue` — shell with **four modes** (monitor / pipeline editor / agent editor / knowledge); localStorage-persisted sidebar + project selection. **Monitor mode polls `/api/tasks` every 1500ms**; other modes pause polling.

### Components (`src/components/`)

| Mode | Components |
|------|-----------|
| Monitor | `ProjectBar` (project selector + CRUD), `TaskList`, `PipelineView` (VueFlow graph + draggable flow profiles), `PipelineNode`, `QaPanel`, `ArtifactPanel` (renders markdown via `marked`) |
| Pipeline Editor | `PipelineEditor` (VueFlow canvas, largest component), `PipelineEditorNode`, `StepConfigPanel`, `CatalogPanel`, `RulesPanel`, `ProfileManager` |
| Agent Editor | `AgentEditor`, `AgentSectionEditor`, `WorkflowSectionEditor`, `AgentTemplatePicker`, `AgentNlWizard` (NL→draft generation) |
| Knowledge | `KnowledgePanel` |
| Shared | `RailIcon` (sidebar icons) |

### Libs (`src/lib/`)

- `agentMarkdown.js` — agent-markdown round-trip (`parseAgentMarkdown` / `compileAgentMarkdown` / `draftFromAgentMarkdown` / `heuristicDraftFromDescription` / section helpers). **Shared by frontend and backend** (`devTeamApi.js` imports it).
- `workflowSteps.js` — parse/compile workflow section markdown ↔ builder steps.
- Composables: `useAsyncState`, `useDrop`, `useLocalToggle`, `useSearch`, `useSortable`.

## Tooling & conventions

- **Package manager:** bun. **Tests:** bun test (`tests/server`,`tests/mcp`) + vitest (`tests/src`,`tests/shared`) + @playwright/test (`test-e2e/`). See `.claude/rules/testing.md`.
- **E2E** boots the standalone server against `test-e2e/fixtures/.dev-team-agent/` and **attaches** each mode's screenshot to the playwright report (not committed to `docs/`); runs in CI on every push/PR, evidence in the `test-evidence` artifact + PR comment.
- **ESM throughout**; server uses `node:`-prefixed core imports.
- **Defensive filesystem reads** by design: `safeReadDir`, `statSafe`, `readYamlSafe`, `readState`, `loadRegistry` swallow errors and return empty/false rather than throwing — a half-written state file never crashes a request. Preserve this in new scans.
- **Path-traversal hardening** on all request inputs: `resolveArtifact`, `resolveStatic`, `sanitiseProfileName`, `sanitiseAgentName`, `sanitiseSlug`, taskId regex. Keep new file-writing endpoints equally strict.
- **Atomic registry writes** (temp + rename in `saveRegistry`).
- **Outbound fetch of user URLs** must go through `fetchUrlSafe` (https-only, blocks private hostnames).
- Optional `ANTHROPIC_API_KEY` enables NL agent-draft generation (`/api/custom-agents/generate`); falls back to a heuristic when unset.
